# Example Run — Results Summary

Generated by running the pipeline in `--mode mock` (no API key) against the
bundled 15-vendor synthetic dataset. This is a static snapshot, committed so
the resolution + evaluation behavior is inspectable without running anything.

To reproduce:
```
python run.py --input data/synthetic_vendors.csv \
  --output results/example_run/results.csv \
  --cache-out results/example_run/verified_cache_after_run.json
python evaluation/regression_tests/run_tests.py
```

## Judge verdicts across the 15-vendor run

| Verdict | Count |
|---|---:|
| PASS | 13 |
| NEEDS-REVIEW | 2 |
| FAIL-PROCESS / FAIL-GROUNDING | 0 |

Zero fails here isn't the interesting result — the pipeline is expected to
behave correctly on its own synthetic data. The judge's ability to *catch*
process and grounding failures is demonstrated separately in
`evaluation/regression_tests/`, against hand-crafted good and bad traces
(see `judge_regression_test_output.txt`, 7/7 passing).

## Cache growth

The seed cache (`data/verified_cache_seed.json`) started with 1 verified
entry. After this run, `verified_cache_after_run.json` has 13 — every
PASS-graded resolution (except the one that was already a cache hit) got
written back in, keyed by domain. Run it again and V001–V014 would now
resolve straight from the cache too.
